# 진입 경로별 시작 경로

**해당하는 절 하나만 읽는다.** 분기는 프로젝트 유형이 아니라 방문자가 들어오는 경로다. 하나의 레포가 웹앱이면서 라이브러리일 수 있고(Excalidraw), CLI이면서 라이브러리일 수 있다(MarkItDown) — 그럴 때는 **소유자가 첫 방문자에게 보증할 수 있는 경로**를 주 경로로 삼고 나머지는 링크로 보낸다.

모든 절에 공통인 것: 전제조건 → 최소 명령 → **예상 결과**. 셋째 칸을 비우면 방문자는 설치가 성공했는지도 모른다.

## 1. 온라인 체험 — 설치 없이 열리는 것이 있다

가장 강한 경로다. 설치 결정 전에 판단이 끝난다.

- **링크에 이름을 붙인다.** "Try it online", "Playground". 그냥 "Demo"는 GIF인지 웹인지 구별되지 않는다.
- **체험 링크를 설치보다 앞에 둔다.** jq는 7~14번째 줄에서 온라인 체험과 바이너리 링크만 준다. 이미지도 배지도 없다.
- 체험판의 **제약을 함께 쓴다**: 저장 안 됨, 파일 크기 제한, 로그인 필요 여부.
- 체험이 로그인을 요구하면 그건 온라인 체험이 아니다. 아래 5번을 본다.

첫 화면 최소 구성: 한 줄 정의 → 체험 링크 → 결과 이미지 하나 → 설치는 그 아래.

## 2. CLI 설치 — 터미널에서 도는 것

가장 흔하고, 저관심 레포가 가장 자주 놓치는 경로다.

- **패키지 매니저를 나열하지 말고 하나를 추천한다.** 표 하나에 8개 OS를 늘어놓으면 방문자는 자기 것을 찾다가 지친다. 대표 하나 + "다른 플랫폼은 INSTALL.md" 가 낫다. eza는 9개월 시점에 이 분리를 했다.
- **설치 다음 줄에 첫 명령과 그 출력을 붙인다.**

  ```
  $ tool sample-input
  기대되는 출력 두어 줄
  ```

- 셸 연결·PATH 설정이 필요하면 **설치 성공의 확인 방법**을 준다(`tool --version`, `tool doctor`).
- 빌드가 필요하면 필요한 툴체인 버전을 명시한다. "Rust 1.70 이상" 같은 한 줄이 실패 이슈 여러 개를 없앤다.

## 3. import 라이브러리 — 남의 코드 안에서 도는 것

방문자는 "내 프로젝트에 넣었을 때 코드가 어떻게 생기는가"를 본다.

- **설치 명령보다 임포트한 코드 조각이 먼저다.** 세 줄짜리 사용 예제 하나가 기능 목록 스무 개보다 판단에 쓸모 있다.
- **입력과 출력을 함께 보여 준다.** 반환값의 모양(타입·구조)이 통합 가능 여부를 정한다.
- 지원 범위를 명시한다: 언어·런타임 버전, 동기/비동기, 타입 힌트 제공 여부.
- 의존성이 무거우면(모델 가중치, 네이티브 확장) 첫 화면에 쓴다. 이건 아래 "맞지 않는 조건"이다.
- API 레퍼런스 전체를 README에 넣지 않는다. 대표 함수 하나와 링크.

## 4. 호스트 플러그인 — 다른 도구 안에 설치되는 것

Claude Code 스킬, MCP 서버, 에디터 확장, CI 액션. 이 경로에는 **일반 CLI에 없는 세 가지**가 있다.

- **호환 호스트를 첫 문장 옆에 즉시 쓴다.** "Claude Code 스킬", "MCP 서버 (Claude Desktop·Cursor)". 방문자의 첫 질문이 "내 도구에서 되나"이고, 그 답이 없으면 나머지를 읽지 않는다.
- **설치 후 에이전트가 무엇을 할 수 있게 되는지**를 쓴다. 파일이 어디 복사되는지가 아니라. 방문자가 사는 것은 새로운 역량이지 파일이 아니다.
- **설치 경로를 호스트별로 나눈다.** 심링크 / 복사 / 마켓플레이스 / 설정 파일 편집은 서로 다른 명령이다. 짧은 표가 산문보다 낫다.
- **제3자 플러그인의 보안 고지를 쓴다.** 이 코드는 사용자의 에이전트 권한으로 돈다. 무엇을 읽고 무엇을 네트워크로 보내는지, 어떤 권한을 요구하는지 명시한다. 이 장르의 잘 만든 목록들은 이 고지를 관례로 요구한다.
- 호스트가 스킬을 자동으로 고르는 종류라면(Claude Code 스킬) **어떤 요청에서 뜨는지**를 쓴다. 방문자가 그걸 보고 자기 상황과 맞춰 본다.

## 5. 관리자 설정형 통합 — 남이 승인해야 쓰는 것

SaaS 연동, SSO, 조직 단위 배포. 방문자가 혼자 결정할 수 없는 경로다.

- **승인이 필요하다는 사실을 첫 화면에 쓴다.** 이것이 가장 큰 "맞지 않는 조건"이다. 58번째 줄에 두면 방문자는 설치를 시도한 뒤에 알게 된다.
- **필요한 권한을 이름으로 적는다.** "관리자 권한"이 아니라 어떤 역할·스코프인지. 방문자는 그걸 들고 자기 조직의 담당자에게 가야 한다.
- **비용을 적는다.** 유료 API, 좌석 단가, 무료 한도. 없으면 없다고 쓴다.
- **승인 없이 볼 수 있는 것을 준다.** 스크린샷, 샌드박스, 읽기 전용 데모. 없으면 아무도 승인을 요청하러 가지 않는다.
- 데이터가 어디로 가는지 쓴다. 이 경로의 방문자는 거의 항상 그걸 묻는다.

## 경로를 정하고 나서

주 경로 하나를 첫 화면에 완결시키고, 나머지 경로는 **이름을 붙여 링크**한다. React가 Quick Start / 기존 프로젝트 / 새 앱으로 나누고 Excalidraw가 웹 에디터와 npm 통합을 나누는 방식이다. 경로를 섞어 하나의 긴 설치 절로 만들면 어느 방문자에게도 맞지 않는다.
