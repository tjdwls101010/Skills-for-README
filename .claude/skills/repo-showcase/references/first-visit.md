# 첫 화면을 쓴다

README를 쓰거나 고치는 호출에서만 읽는다.

## 모델은 "지금의 bat"이 아니라 "3개월째의 bat"이다

같은 도구 12개(bat·ripgrep·fzf·zoxide·gum·llm·delta·lazygit·rich·fd·eza·rye)의 생성 3개월·9개월·현재 README를 재면 이렇게 자란다.

| | 3개월 | 9개월 | 현재 |
|---|---|---|---|
| 줄수 (중앙값) | 203 | 290 | 514 |
| 설치 헤딩 줄 | 20 | 47 | 74 |
| 첫 40줄 안에 결과 증거 | 10/12 | 12/12 | 11/12 |
| 한 줄 정의 길이 | 62자 | 72자 | 162자 |

**처음 공개하는 레포의 모델은 왼쪽 열이다.** 다만 규칙은 "설치를 몇 번째 줄에 두라"가 아니다 — 아래 표가 보여 주듯 설치 위치는 저관심 레포와 초기 고전을 가르지 못한다.

**실제 기준은 이것이다: 방문자가 설치를 결정하기 전에 판단할 재료를 다 받았는가.** 지금의 fzf가 설치를 108번째 줄에 둘 수 있는 것은 그 앞이 전부 "이게 무엇이고 무엇을 해 주는가"이기 때문이다. 빌드 설명이 길어야 하는 신규 레포도 마찬가지다 — 긴 설명을 앞으로 당기는 게 아니라, **판단 재료를 앞에 두고 긴 설명을 뒤로 보낸다.**

## 저관심 레포와 갈라지는 지점

별 0~4개의 최근 개인 레포 20개와 위 12개의 3개월 시점을 나란히 두면 이렇게 갈린다.

| | 저관심 20개 | 초기 고전 12개 |
|---|---|---|
| 첫 40줄 안에 결과 증거 | **7/20** | **10/12** |
| 결과 이미지가 아예 없음 | **16/20** | 1/12 |
| 첫 결과 이미지 줄 (중앙값) | 78 | 9 |
| 한 줄 정의 길이 | **138자** | **62자** |
| 아는 도구·작업을 지목 | **0/20** | **4/12** |
| description 길이 | 126자 | — |
| description이 검색에서 잘림 | **8/20** | — |
| 줄수 | 220 | 203 |
| 설치 헤딩 줄 | 73 | 20 |

**아래 두 줄이 중요하다.** 줄수와 설치 위치는 두 집단을 가르지 못한다. "짧게 써라", "설치를 맨 위로"는 이 코퍼스가 뒷받침하지 않는다. 가르는 것은 **첫 화면에 결과가 있는가**와 **정의가 방문자의 어휘로 되어 있는가**다.

## 세 질문의 답을 첫 화면에 넣는다

### 이게 뭔가 — 한 줄 정의

방문자가 **이미 아는 것**에 연결한다.

- `A cat(1) clone with syntax highlighting and Git integration.` (bat, 3개월)
- `fd is a simple, fast and user-friendly alternative to find.` (fd, 3개월)
- `A faster way to navigate your filesystem.` (zoxide, 3개월)

셋 다 방문자가 이미 쓰는 도구나 이미 하는 작업을 지목한다. 반대쪽은 이렇게 생겼다.

> TaskWeaver is a next-generation, extensible orchestration substrate that unifies heterogeneous execution primitives under a single declarative control plane…

틀린 말이 하나도 없는데 방문자는 자기 상황에 대입할 수 없다. **"이 문장을 읽고 방문자가 자기 말로 다시 말할 수 있는가"**가 판정 기준이다.

레포에 가까운 대안이 없으면 억지로 만들지 않는다. 대신 **없애 주는 반복 작업**을 지목한다 — 그것도 방문자가 아는 것이다.

### 나한테 맞나 — 맞지 않는 조건까지

**도입을 막을 수 있는 조건은 첫 화면에 둔다.** 관리자 권한, 유료 계정, 특정 OS, 실험 단계. 뒤에 숨기면 방문자는 설치까지 해 보고 나서 알게 되고, 그때의 손해는 처음부터 안 것보다 크다.

필수와 선택을 나눈다. zoxide 3개월 README는 필요한 셸 연결과 선택적인 fzf를 나눠 적는다. 반대로 어떤 레포는 인증·Node 요구사항을 3번째 줄에 쓰면서 정작 도입을 막는 M365 관리자 권한은 58번째 줄에 둔다.

**현재 상태와 지원 범위는 홍보 문구보다 먼저다.** rye는 현재 README 16~22번째 줄에서 개발 중단과 uv로의 이전 경로를 앞세운다. 방문자의 시간을 아끼는 쪽이 결국 신뢰를 만든다.

### 어떻게 써보나 — 첫 성공까지

설치 명령까지가 아니라 **첫 결과까지** 이어져야 한다. llm의 3개월 README는 설치 → 키 저장 → 질문 → 실제 출력을 한 흐름으로 보여 준다.

```
$ fdx netfl
netflix/
netflix/client.rs
```

이 블록 하나가 "설치하면 무엇이 나오는가"에 답한다. 명령만 있는 블록은 답하지 않는다.

## 비교표는 조건과 손해까지 쓴다

fd의 3개월 README는 벤치마크에 **약 100만 파일, 양쪽 동일한 결과 14,030개**라는 조건을 밝히고, `find -iname`이면 속도가 비슷하다고 인정한다. 이 정직함이 나머지 수치를 믿게 만든다.

- **인용 수치를 제품 성능처럼 쓰지 않는다.** 외부 연구의 "42% → 78%"는 그 연구의 수치이지 이 도구의 수치가 아니다. 출처와 조건을 함께 쓰거나, 쓰지 않는다.
- **손해를 적는다.** 무엇을 포기했는지 없는 비교표는 광고로 읽힌다.
- 대안 레포를 깎아내리지 않는다. 대안의 사용자가 이 레포의 방문자다.

## 모순 하나가 판단을 멈춘다

풍부한 문서도 모순 하나면 거기서 읽기를 멈춘다.

- 58~64번째 줄에서 "SDK는 transport adapter다"라고 쓰고 107~112번째 줄에서 "아직 아니다"라고 쓴 레포
- 110~116번째 줄에서 사용 예제로 보여 준 이메일·Telegram 싱크가 166~167번째 줄 로드맵에서는 예정 기능인 레포

`audit_repo.py`의 `status_contradiction`이 이 형태를 찾지만 전부 찾지는 못한다. **README를 다 쓴 뒤 예제에 등장하는 기능이 전부 지금 동작하는지 직접 확인한다.**

## 따르지 않는 규칙

널리 인용되지만 이 코퍼스가 뒷받침하지 않는 것들이다. 하지 말라는 뜻이 아니라, **근거 없이 따르지 말라**는 뜻이다.

- **"description은 120자 미만"·"100줄 넘으면 목차 필수"·고정된 섹션 순서** (Standard README). 형식 규약이지 방문자 판단 속도의 임계값이 아니다. description에 실제로 걸리는 제약은 따로 있고, 측정값과 조건은 `beyond-readme.md`에 있다.
- **"너무 짧기보다 긴 편이 낫다"** (Make a README). eza는 3개월 428줄에서 9개월 165줄로 **줄이면서** 설치를 별도 파일로 뺐다.
- **배지·로고·기술 스택을 맨 위에** (Best-README-Template). 인기 24개 중 8개가 배지 0개이고, jq는 배지 0개에 35,565 stars다. 배지는 개별 질문의 답이지 품질 점수가 아니다.
- **README를 코드보다 먼저 쓰면 더 좋은 프로젝트가 된다** (RDD). 작성 순서와 성과를 이은 자료가 없다.
- **커뮤니티 파일·웹사이트·소셜 미리보기가 성장시킨다.** 이 기능들의 **노출·분류 효과**와 **전환 효과 주장**은 다른 것이다. SECURITY는 인기 레포도 절반 이하가 가지고 있다.

## 결과 증거의 매체를 고른다

**입증할 대상이 매체를 정한다.** 강한 순서 같은 건 없다.

| 보여 줄 것 | 매체 |
|---|---|
| 결과물의 외형 (렌더된 화면, 생성된 이미지, 그린 표) | 정지 스크린샷 |
| 조작 과정 (여러 단계를 거쳐 결과에 이르는 흐름) | GIF·영상 |
| 텍스트 출력 (CLI 결과, 로그, 변환 결과) | 명령과 출력을 함께 담은 코드 블록 |
| 반환값의 모양 (라이브러리) | 입력 코드와 출력값을 함께 담은 코드 블록 |
| 직접 만져 봐야 아는 것 (에디터, 캔버스) | 온라인 체험 링크 |

CLI라고 무조건 GIF가 아니다. llm의 초기 README는 이미지 없이 출력 텍스트만으로 충분히 보여 준다. 반대로 GUI 도구에 터미널 GIF를 만드는 것은 입증할 대상과 매체가 어긋난 경우다.

### 터미널 데모를 고르기로 했다면

`vhs`가 있으면 테이프 파일을 쓰고 실행한다. 없으면 테이프만 남기고 소유자에게 알린다.

```tape
# demo.tape — vhs demo.tape 로 demo.gif 생성
Output demo.gif
Set FontSize 18
Set Width 1000
Set Height 500
Type "fdx netfl"
Enter
Sleep 2s
```

- **명령 하나와 그 결과 하나**로 끝낸다. 기능 소개를 다 담으려는 GIF는 아무것도 전달하지 못한다.
- 첫 화면에 두고, alt 텍스트에 **무엇을 하는 장면인지** 쓴다. `alt="demo"`는 스크린리더 사용자에게 아무것도 주지 않는다.
- 파일이 크면 첫 화면 로딩이 느려진다. 5MB를 넘으면 프레임 수나 길이를 줄인다.

## 한국어 README

기본은 영어다. GitHub 검색과 유입이 영어로 일어난다. 소유자가 한국어를 요청하면 `README.ko.md`를 따로 만들고 두 파일 맨 위에 서로를 가리키는 한 줄을 넣는다.

```markdown
English | [한국어](README.ko.md)
```

번역이 아니라 **같은 판단 재료를 각 언어로** 준다. 한쪽만 최신인 상태가 되면 오래된 쪽이 더 해롭다 — 유지할 수 없으면 만들지 않는다.
